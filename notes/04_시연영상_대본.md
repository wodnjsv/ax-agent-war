# W01 시연 영상 녹화 계획·대본

기준: 제출 답안 `03_제출답안_초안.md` 1~7번, 대회 숙지 정리, A04 3절 「대표 실행 사례」, 현재 화면 코드. 2026-11-15 로컬 API 예행 결과를 반영했습니다.

**본편 목표는 5분 10초입니다. 초기화로 구분하는 녹화는 A~D 네 번입니다.** A는 담당자가 직접 등록·상신·확정하고, B~D는 마케팅 행동과 다른 부서 회신을 모의 입력으로 진행합니다. 모의 입력 뒤 계산·판정·계획·상태 갱신은 시스템이 실행합니다. 날짜 이동 중간에도 멈춰서 증거를 촬영합니다.

아래의 **실제 녹화 시간은 촬영 예산**입니다. 배포본에서 초시계로 잰 값이 아닙니다. 날짜 대기는 사용자 확인값인 영업일당 약 3초, AI 대기는 호출당 최대 30초로 잡았습니다. 현장에서는 실제 시간을 측정해 자막의 초 수와 편집 길이를 바꿉니다. 로컬 API 실행 속도를 배포본 속도로 쓰지 않습니다.

## 1. 녹화 전 준비

1. 배포본에 접속합니다. **접속 화면에서 비밀번호 입력**. 로그인 장면은 본편에서 제외합니다. 주소·비밀번호·API 키를 대본이나 자막에 넣지 않습니다.
2. 브라우저 콘텐츠 영역을 가능하면 1920×1080, 확대율 100%로 맞춥니다. 글자가 작으면 창을 좁히기보다 녹화 해상도·편집 확대를 조정합니다. 알림과 다른 창을 닫습니다. 시스템 날짜와 가상 일자를 혼동하지 않도록 화면 상단 가상 일자를 항상 남깁니다.
3. 시작 화면은 `내 기안`입니다. `데이터 흐름`은 소개에서는 닫고, 등록 결과와 근거를 설명할 때 엽니다. 한 화면에 카드 여러 개를 작게 넣지 말고 읽는 카드만 스크롤해 크게 보여 줍니다. 창의 열림 상태는 초기화해도 남으므로 컷마다 확인합니다.
4. 초기화는 상단 `모의 입력` → `전체 초기화(07-01부터)` → 확인창 `초기화`입니다. **초기화는 시나리오와 직접 처리 설정을 지우지 않습니다.** 07-01인지 확인한 다음 **`내 기안`으로 돌아와** `데이터 흐름` 하단 `시연 조작`에서 체크박스와 기안별 처리 방식을 따로 맞춥니다.
5. A는 두 시나리오를 모두 끕니다. PLAN-001~003만 직접 처리, 나머지는 자동 처리로 맞춥니다. 버튼은 현재 상태에 따라 `PLAN-002 직접 처리로` 또는 `PLAN-002 자동 처리로`처럼 표시됩니다. 원하는 상태로 바꾼 뒤 반대 동작의 버튼이 나오는지 확인합니다.
6. B~D도 07-01에서 먼저 PLAN-001~003을 직접 처리로 맞춥니다. 첫 날짜 진행 안내창에서 **`모두 자동 처리로 바꾸고 진행`**을 눌러 전체 자동으로 시작하는 모습을 촬영합니다. A에서는 항상 **`그대로 진행`**을 누릅니다. 이 선택을 바꾸면 A의 확정 주체와 날짜가 달라집니다.
7. 배포본 AI 연결을 촬영 전에 확인합니다. 성공한 수요 정리 결과와 승인 초안의 AI 표시·모델 기록을 확인합니다. 대기 문구만으로 성공을 판단하지 않습니다. 키 없는 로컬 예행은 직접 값 등록·양식 초안으로 했으므로, 실제 AI 응답 내용과 소요 시간은 현장 확인 대상입니다.
8. 같은 탭에서 이동할 책갈피를 준비합니다. 주소의 경로 부분은 `#/`(내 기안), `#/mock`(모의 입력), `#/w/PLAN-002`, `#/w/PLAN-004`, `#/w/PLAN-005`, `#/w/PLAN-011`, `#/w/PLAN-014`, `#/w/PLAN-001`입니다. 여러 탭에서 동시에 날짜를 진행하지 않습니다. 일반 조작은 아래 진행표대로 합니다.

### 공통 조작: 진행표에서 이 표현을 쓰면 다음처럼 누릅니다

| 표현 | 실제 조작 |
|---|---|
| 기안 열기 | 상단 상세 근거의 `기안 목록` → 해당 PLAN ID → `업무 화면으로`. 준비한 `#/w/PLAN-…` 책갈피로 바로 열어도 같습니다. `#/plan/…`은 상세 근거 화면이고 `#/w/…`은 담당자 업무 화면입니다. |
| 날짜까지 진행 | 상단 `모의 입력` → 상단 **`이 날짜까지` 날짜 칸**에 지정 일자 입력 → `진행`. 직접 처리 안내가 뜨면 A는 `그대로 진행`, B~D의 첫 진행은 `모두 자동 처리로 바꾸고 진행`. 아래쪽 날짜 지름길 버튼은 쓰지 않습니다. |
| 하루 진행 | 상단 `다음 날로`. 직접 처리 안내가 뜨면 A에서는 `그대로 진행`. 업무 화면을 유지하며 확인할 때 씁니다. |
| 근거 읽기 | 기안 상세의 `근거`에서 `공급`, `공급 확약`, `승인`, `보충 발주`, `현금 영향` 중 지정한 행을 짚습니다. 숫자는 `숫자와 상세 보기`를 펼칩니다. |
| 흐름 카드 읽기 | 상단 `데이터 흐름` → 오른쪽 `방금 일어난 일` → 해당 날짜·기안의 카드. `사용한 데이터` → `규칙` → `결과` → `다음` 순으로 짚습니다. 입력이 접혀 있으면 `나머지 N개 보기`, 이전 행동이면 `그 전에 일어난 일 N건`을 누릅니다. N은 화면값입니다. |
| 사건 기록 찾기 | 해당 기안을 연 상태에서 데이터 흐름 하단 `이 기안의 사건 기록`. 또는 상단 `사건 기록` → `기안`에서 해당 PLAN ID → `보기`. 날짜·사건명·내용으로 찾고 사건 번호는 녹화 화면값을 사용합니다. |

데이터 흐름은 최근 행동 그룹을 중심으로 보여 줍니다. **07-10 현금·승인 경로, 07-13 원료 지연, 08-06 Corevia 불가 회신은 그 날짜에 촬영**합니다. 나중에 최종 화면에서 모두 찾으려 하지 않습니다. 확정·철회 뒤에는 다음 조치·권장 대안 일부가 숨겨지므로 대안은 종료 전에 촬영합니다.

## 2. 네 번의 녹화와 컷별 시작·끝

| 녹화 | 시작 상태 | 진행·촬영 순서 | 끝 상태·용도 |
|---|---|---|---|
| A · 직접 처리 | 초기화 07-01, 시나리오 없음, 직접 처리 001~003 | 소개 → PLAN-002 문장 정리 → **예시 값으로 고정 후 등록** → 초안 확인·상신 → 07-02 → 07-03 직접 확정. 이어서 다른 직접 기안은 입력하지 않고 07-20까지 진행합니다. | 정상 장면은 07-03에서 끝냅니다. 07-20 PLAN-001의 `담당자 입력 없음` 경위는 장면 6용 별도 구간 A-extra입니다. |

**한 컷으로 이어 가지 않는 이유:** A에서 PLAN-002를 07-01에 직접 등록하면 전체 자동 경로의 07-07 수요 회신과 출발 조건이 다릅니다. 직접 처리 001·003을 남겨 두면 별도의 기한 경과도 생깁니다. 따라서 A의 기록을 B의 전체 결과와 합산하지 않습니다. B 시작에 `초기화 후 별도 실행 · 전 기안 자동 처리` 자막을 넣습니다.

### 촬영하되 본편에서 덜어내는 준비·대기

아래는 배속으로 위장하지 않고 **편집에서 통째로 제외하는 구간**입니다. 전환 자막으로 실행 조건과 날짜 점프를 밝힙니다. 중간에 필요한 사건은 정차해 별도로 촬영합니다.

| 구간 | 실제 녹화 시간 예산 | 배율 | 본편 길이 | 연결 표기 |
|---|---:|---|---:|---|
| 접속·로그인·창 설정·초기화·기안 찾기 연습 | 현장 확인 | 해당 없음, 제외 | 0초 | 로그인 정보 노출 없음 |
| A 07-03→07-20, 001·003 방치 확인 준비 | 약 33초 + 조작 | 해당 없음, 제외 | 0초 | 장면 6에 `별도 확인: 직접 처리 유지 · 07-20` |
| B 07-16→07-20 | 약 6초 + 조작 | 해당 없음, 제외 | 0초 | 장면 4 시작에 `기본 · 07-20` |
| C 07-01→07-16 | 약 33초 + 조작 | 해당 없음, 제외 | 0초 | `초기화 후 별도 실행 · CEO 15억 조건(가정) · 07-16` |
| C 07-21→08-13 | 약 51초 + 조작 | 해당 없음, 제외 | 0초 | `같은 거절 시나리오 · 08-13` |
| D 07-01→07-10 | 약 21초 + 조작 | 해당 없음, 제외 | 0초 | `초기화 후 별도 실행 · 회수일 지연 · 07-10` |
| B·C·D의 09-14 최종 확인 | 녹화 불필요. 로컬 예행에서 완료 | 해당 없음 | 0초 | 09-14 전체 결과를 08-14 화면의 결과처럼 말하지 않음 |

## 3. 본편 시간표

| 장면 | 완성 영상 구간 | 길이 | 제출 답안 연결 |
|---|---|---:|---|
| 1 소개 | 00:00~00:30 | 30초 | 1번: 업무·사용자·결정 |
| 2 정상 | 00:30~02:10 | 100초 | 2·5·6번: 입력→근거→승인→상태 기록 |
| 3 조건 변경 | 02:10~03:05 | 55초 | 2·4번: 현금·원료 지연에 따른 재검증 |
| 4 정보 부족·거절 | 03:05~04:15 | 70초 | 3·4·6번: 미확인, 대안, 위험 수용·철회 |
| 5 필수 확장·부서 영향 | 04:15~04:45 | 30초 | **3번과 4번**: 앞 장면의 실제 반영 위치 재확인 |
| 6 추가 확장·한계 | 04:45~05:10 | 25초 | **7번**: 회수 지연·민감도·직접 처리 방치 |
| 합계 | 00:00~05:10 | **310초** | 정속 근거 화면을 우선 확보 |

**촬영과 낭독:** 화면을 먼저 조작해 녹화한 뒤 같은 구간에 내레이션을 얹어도 됩니다. 표의 `이동 여유 N초(제외)`는 기안 찾기·스크롤·커서 정렬을 위해 더 녹화하는 시간입니다. 이 여유만 편집에서 덜어내고 입력·확인·실행 버튼, 판단 결과와 근거는 남깁니다. 1배속 행의 촬영 시간이 완성 길이보다 길어도 배속한 것이 아닙니다. 2-8의 날짜 버튼·안내창 선택은 2-7 말미와 2-9 초반의 정속 예산에 포함하며 실제 순서대로 대기 구간 사이에 배치합니다.

내레이션은 정속 화면에서 읽습니다. 배속 대기에는 내레이션을 넣지 않고 시스템 대기 모습을 남깁니다. 실제 AI 대기가 30초보다 짧으면 `실측 초÷8`만 남기고, 줄어든 시간은 결과·근거를 읽는 정속 화면에 보탭니다. 각 조작을 지나치게 서두르기보다 녹화 후 이동 중의 무음 여백을 덜어냅니다.

### 확인하지 못한 것·현장 점검

- 배포본의 코드·데이터가 로컬과 동일한지, 로그인 이후 화면 배치·글자 가독성·스크롤 위치, 버튼을 직접 눌렀을 때의 전체 동선은 현장에서 확인해야 합니다. 화면값이 다르면 예정 대사를 읽지 말고 해당 상태를 확인한 뒤 촬영 경로를 다시 맞춥니다.
- 실제 OpenRouter 호출 성공, 모델명, AI 정리값·초안 문장, 두 호출의 실제 대기 시간은 미확인입니다. 결과가 없는데 성공이라고 말하지 않습니다. 예시 값으로 등록값을 고정하는 이유가 이 변동성을 분리하기 위해서입니다.
- 영업일당 약 3초 및 08-14까지 약 100초는 배포본에 대한 사용자 제공 기준입니다. 07-01→08-14는 32영업일 진행으로 대기 예산 약 96초이며, 실제 렌더링·조작·통신 시간이 더해집니다. 본편에서는 대기만 배속하고 카드 읽기는 정속으로 둡니다.
- 310초는 편집 설계 합계이며 실제 음성 녹음 시간은 미측정입니다. 각 행 대사를 한 번 읽어 넘치면 추가 확장부터 줄입니다. 핵심 근거의 가독성을 위해 말과 화면을 배속하지 않습니다.
- 위험 수용과 철회의 대표 실행 증거는 **PLAN-011 한 건**입니다. 정기 보충 발주의 지급은 민감도 범위이고, Corevia 원료·생산 일정의 자체 계산은 구현 범위 밖입니다.
